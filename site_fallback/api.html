# API Reference

## API Endpoints (resumen)

La aplicación expone una API REST construida con FastAPI. A continuación los puntos de entrada principales:

- `GET /` : raíz con versión y link a `/docs`
- `GET /health` : comprobación de estado

### Users
- `POST /users/` : crear usuario (payload según `UserCreate`)
- `GET /users/` : listar usuarios
- `GET /users/{user_id}` : obtener usuario por id
- `PATCH /users/{user_id}` : actualizar parcialmente
- `DELETE /users/{user_id}` : eliminar usuario

### Rooms
- `POST /rooms/` : crear habitación
- `GET /rooms/` : listar habitaciones
- `GET /rooms/{room_id}` : obtener habitación por id
- `PATCH /rooms/{room_id}` : actualizar habitación
- `DELETE /rooms/{room_id}` : eliminar habitación

### User History
- `POST /user-history/` : registrar acción/historial de usuario
- `GET /user-history/{user_id}` : obtener historial por usuario
- `DELETE /user-history/{history_id}` : eliminar registro de historial

### Modelos (síntesis)

`User` (resumen): identificador, nombre y correo. En código se accede mediante getters: `get_id()`, `get_name()`, `get_email()`.

`Room` (resumen): número, tipo y estado. Métodos: `get_room_number()`, `get_room_type()`, `get_status()`, `set_status()`.

`UserHistory`/registros: se usan para auditar acciones (check-in, reserva, etc.) y guardan referencias a usuario y habitación, timestamps y descripción.

La documentación interactiva está en `/docs` (FastAPI) cuando el servidor está en marcha.
